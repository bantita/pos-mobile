## รองรับ .xlsx หรือไม่: รองรับ (SheetJS 0.20.3 จาก CDN ทางการ)

- ติดตั้ง: `npm --prefix d:\pos-mobile\.worktrees\impexp install https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz` (ไม่ได้ใช้ `xlsx@0.18.5` จาก npm) test ยืนยัน `XLSX.version === '0.20.3'`
- Bundling (Expo 51 / metro): ครั้งแรกล้มเหลว เพราะ metro เลือกฟิลด์ `module` ของแพ็กเกจ (`xlsx.mjs`) แต่ `metro.config.js` ของโปรเจกต์กำหนด `sourceExts` ไว้โดยไม่มี `mjs` วิธีแก้คือ lazy-import `xlsx/dist/xlsx.full.min.js` แทน ซึ่งเป็น build สำเร็จรูปของ SheetJS เองที่ไม่มี `require()` เลย จึงไม่ต้องแก้ metro config และไม่ต้องมี shim ของ `fs`/`stream` ส่วน type ใช้ชุดเดียวกับ `xlsx` ผ่าน `src/types/xlsx-dist.d.ts`
- ผลรัน `npx --prefix D:\pos-mobile\.worktrees\impexp expo export --platform web --output-dir D:\pos-mobile\.worktrees\impexp\.tmp-web-export` (cwd `D:\pos-mobile\.worktrees\impexp`) สำเร็จ ได้ `index-*.js` 4.32 MB และ chunk แยก `xlsx.full-*.js` 1.23 MB (โหลดเมื่อใช้ .xlsx ครั้งแรกเท่านั้น) ลบโฟลเดอร์ทิ้งแล้ว
  - หมายเหตุ: ถ้ารันด้วย path ที่ขึ้นต้นด้วย `d:` ตัวเล็ก metro จะขึ้น `SHA-1 ... is not computed` ซึ่งเป็นปัญหาตัวพิมพ์ของ drive letter บน Windows ไม่เกี่ยวกับงานนี้ ใช้ `D:` แล้วผ่าน
- ไฟล์ .xlsx: รหัส/บาร์โค้ด/เลขภาษี/เบอร์โทรเขียนเป็นข้อความ (ไม่กลายเป็น 8.85E+12 และ 0 นำหน้าไม่หาย) คอลัมน์ราคา/จำนวนเขียนเป็นตัวเลข ตอนอ่านใช้ค่าดิบแล้วแปลงเป็นข้อความเอง (บาร์โค้ดที่ผู้ใช้พิมพ์เป็นตัวเลขใน Excel จึงยังอ่านได้ครบหลัก)
- CSV: UTF-8 มี BOM (Excel อ่านภาษาไทยได้), CRLF, ครอบ quote เมื่อจำเป็น ตอนอ่านรองรับ BOM, CRLF/LF/CR, comma และขึ้นบรรทัดใหม่ภายใน quote และถ้าไฟล์ไม่ใช่ UTF-8 จะลองถอดเป็น Windows-874 (CSV ภาษาไทยจาก Excel รุ่นเก่า) ค่าที่ขึ้นต้นด้วย `= + @ -` (ที่ไม่ใช่ตัวเลข) จะถูกเติม `'` นำหน้าตอน export เพื่อกัน CSV/formula injection และถอดออกเองตอน import
- นำเข้าได้ทั้ง `.xlsx`, `.xls`, `.csv` นามสกุลอื่นจะขึ้น "รองรับเฉพาะไฟล์ .xlsx และ .csv" และไฟล์ที่ใหญ่เกิน 10MB จะขึ้น "ไฟล์มีขนาดเกิน 10MB"

## Variants (ตัวเลือกสินค้า): รวมอยู่ในไฟล์แล้ว

- `.xlsx` อยู่ในชีต `ตัวเลือกสินค้า` ส่วน `.csv` อยู่ในไฟล์เดียวกัน ใต้แถวคั่นที่ช่องแรกเป็น `[ตัวเลือกสินค้า]`
- การกำหนดตัวเลือกใช้คอลัมน์ `ตัวเลือกสินค้า` ในตารางสินค้า รูปแบบ `สี=แดง|น้ำเงิน; ไซส์=M|L`
- ตอน import ถ้าสินค้านั้นมีแถวในตาราง variant จะแทนที่ variants ทั้งชุด โดยคง id เดิมไว้เมื่อค่าตัวเลือกตรงกัน ถ้าไม่มีแถวและคอลัมน์ตัวเลือกว่าง variants เดิมจะไม่ถูกแตะ ถ้าเปลี่ยนตัวเลือกแต่ไม่ส่งแถว variant และ variants เดิมไม่เข้ากับตัวเลือกใหม่ จะถือเป็นข้อผิดพลาด
- ตรวจว่าบาร์โค้ด variant ต้องไม่ซ้ำทั้งระบบ (รวมบาร์โค้ดหน่วย) ค่าตัวเลือกต้องมีอยู่ในตัวเลือกของสินค้า ต้องครบทุกตัวเลือก และ combination ห้ามซ้ำ

## Column spec (หัวคอลัมน์ภาษาไทย = แถว 1; ใช้ machine key แทนได้; ชีต `คำอธิบาย` ใน Template .xlsx อธิบายทุกคอลัมน์)

การจับคู่หัวคอลัมน์ทำแบบตรงตัวหลัง normalize (ตัดช่องว่าง/ไม่สนตัวพิมพ์) กับ header, key หรือ alias ไม่ใช้ `includes()` แบบเดิม คอลัมน์ที่ไม่รู้จัก (เช่น หมายเหตุ) จะถูกข้าม

### สินค้า — ชีต `สินค้า` (1 แถว = 1 หน่วยนับ, ข้อมูลระดับสินค้าซ้ำได้ทุกแถว, จัดกลุ่มตามรหัสสินค้า)

| หัวคอลัมน์ | key | กฎ |
|---|---|---|
| รหัสสินค้า * | code | ใช้ upsert |
| ชื่อสินค้า * | name | |
| ประเภทสินค้า | productType | ทั่วไป / บริการ (ว่าง = ทั่วไป) |
| หมวดหมู่/กลุ่ม | category | ชื่อ จับคู่แบบไม่สนตัวพิมพ์/ช่องว่าง ถ้าไม่มีจะสร้างใหม่ |
| แบรนด์ | brand | ชื่อ ถ้าไม่มีจะสร้างใหม่ |
| ผู้จำหน่าย | supplier | ชื่อ ถ้าไม่มีจะสร้างใหม่ |
| หน่วย * | unit | ห้ามซ้ำในสินค้าเดียวกัน |
| อัตราส่วน (ต่อหน่วยฐาน) | ratio | > 0, ว่าง = 1 |
| หน่วยหลัก (Y/N) | isBase | ต้องมี 1 หน่วยพอดี และอัตราส่วนต้องเป็น 1 |
| หน่วยเริ่มต้น POS (Y/N) | isDefault | ว่าง = เท่ากับหน่วยหลัก, Y ได้ไม่เกิน 1 |
| บาร์โค้ด | barcodes | หลายค่าคั่นด้วย `\|` ห้ามซ้ำทั้งไฟล์และทั้งระบบ |
| ราคาทุน | costPrice | ≥ 0, ว่าง = 0 |
| ราคาขาย * | salePrice | ≥ 0 |

| ตัวเลือกสินค้า | options | `สี=แดง\|น้ำเงิน; ไซส์=M\|L` |

ไม่มีคอลัมน์ หมายเหตุ/รายละเอียด เพราะ `ProductMaster` ไม่มี field description (ไม่ได้เพิ่ม field ใหม่ในโมเดล) ถ้าแนบคอลัมน์ หมายเหตุ มาก็จะถูกข้าม ช่องที่ไม่บังคับซึ่งเว้นว่างตอนอัปเดตจะคงค่าเดิม ส่วน template แบบเดิม (`รหัสสินค้า,ชื่อสินค้า,หมวดหมู่,หน่วย,ราคาทุน,ราคาขาย,บาร์โค้ด,หมายเหตุ`) ยังนำเข้าได้

### สินค้า — ชีต `ตัวเลือกสินค้า`
รหัสสินค้า * (code) · ค่าตัวเลือก * (optionValues, `สี=แดง; ไซส์=M`) · SKU ตัวเลือก (sku) · บาร์โค้ดตัวเลือก (barcode) · ราคาตัวเลือก (price, ว่าง = ใช้ราคาสินค้า) · สต๊อกตัวเลือก (stockQty)

### หมวดหมู่ — ชีต `หมวดหมู่`
ชื่อหมวดหมู่ * (name, upsert ตามชื่อ) · หมวดหมู่หลัก (parent, ชื่อ ต้องมีในระบบหรือในไฟล์ ระบบจะสร้างหมวดหลักก่อนและตรวจการวนซ้ำ) · สถานะ (status) · จำนวนสินค้า (มีเฉพาะตอน export ไม่ใช้ตอน import)

### แบรนด์ — ชีต `แบรนด์`
ชื่อแบรนด์ * (name, alias ยี่ห้อ, upsert ตามชื่อ) · สถานะ · จำนวนสินค้า (มีเฉพาะตอน export)

### ผู้จำหน่าย — ชีต `ผู้จำหน่าย`
ชื่อผู้จำหน่าย * (name) · เลขผู้เสียภาษี (taxId, ตัวเลข 13 หลัก ตัด `-`/ช่องว่างออกให้) · เบอร์โทร (phone) · ผู้ติดต่อ (contactName) ลำดับการ upsert คือจับคู่ด้วยเลขผู้เสียภาษีก่อน ถ้าไม่เจอจึงจับคู่ด้วยชื่อ ถ้ายังไม่เจอจะสร้างใหม่ (ตรงกับ type `Supplier` ที่มีแค่ 4 field นี้)

### ตัวอย่างข้อความข้อผิดพลาด
`แถว 8: ราคาขายต้องเป็นตัวเลข` · `แถว 12: บาร์โค้ด 8850999000001 ซ้ำกับสินค้า P001` · `แถว 14: บาร์โค้ด 885… ซ้ำในไฟล์ (แถว 13)` · `สินค้า P010 ไม่มีหน่วยหลัก` · `สินค้า P011 มีหน่วยหลักมากกว่า 1 หน่วย` · `สินค้า P012: หน่วยหลักต้องมีอัตราส่วน 1` · `แถว 9: VAT รวมในราคาต้องเป็น Y หรือ N` · `แถว 11: อัตรา VAT ต้องเป็น 0 หรือ 7` · `ตัวเลือกสินค้า แถว 3: ตัวเลือก สี=เขียว ไม่มีในตัวเลือกของสินค้า P022` · `แถว 4: เลขผู้เสียภาษีต้องเป็นตัวเลข 13 หลัก` · `ชีต สินค้า: ไม่พบคอลัมน์ที่จำเป็น: ราคาขาย`
ถ้าสินค้าตัวไหนมีข้อผิดพลาดแม้แต่แถวเดียว (รวมแถว variant ของมัน) จะถูกข้ามทั้งตัว ส่วนตัวอื่นยังนำเข้าได้หลังกดยืนยัน มาสเตอร์ใหม่จะถูกสร้างเฉพาะที่สินค้าซึ่งผ่านการตรวจใช้อยู่ id ใหม่ไม่มี `_` (`p…`, `u…`, `v…`)

### Audit log
ทุกการยืนยันนำเข้าเรียก `logAction(<สินค้า|หมวดหมู่|แบรนด์|ผู้จำหน่าย>, 'นำเข้าข้อมูล', 'นำเข้า…: เพิ่ม X อัปเดต Y ไม่เปลี่ยนแปลง Z [สร้างมาสเตอร์ใหม่ N] ข้าม E รายการ', { created, updated, unchanged, mastersCreated, skipped, errors })` หนึ่งครั้งต่อการนำเข้า (ส่วนมาสเตอร์ที่สร้างอัตโนมัติจะถูกบันทึก "เพิ่ม" แยกโดย store เหมือนเดิม)

## วิธีทดสอบด้วยตัวเอง (เว็บ back-office)

   - กด Download Template เลือก .xlsx หรือ .csv แล้วเปิดใน Excel จะเห็นภาษาไทยอ่านได้ มีน้ำดื่ม P9001 (ขวด อัตราส่วน 1 มี 2 บาร์โค้ด / แพ็ค 6 / ลัง 24), บริการ P9002, เสื้อ P9003 ที่มี 2 variants และชีต คำอธิบาย
   - แก้หรือเพิ่มแถว แล้วกด เลือกไฟล์ → modal แสดงจำนวน เพิ่มใหม่ / อัปเดต / ไม่เปลี่ยนแปลง / สร้างมาสเตอร์ใหม่ / ข้อผิดพลาด พร้อมรายการข้อผิดพลาด → กด ยืนยันนำเข้า N รายการ → สินค้าโผล่ในแท็บ รายการสินค้า และหมวดหมู่/แบรนด์ใหม่โผล่ในแท็บ มาสเตอร์
   - กด Export (.xlsx หรือ .csv) แล้วตรวจว่าจำนวนบนการ์ดตรงกับ `products.length` จากนั้นนำไฟล์นั้นกลับเข้ามาทันที → ต้องได้ เพิ่มใหม่ 0, อัปเดต 0, ข้อผิดพลาด 0 และปุ่มยืนยันขึ้น "ไม่มีรายการที่ต้องบันทึก"
   - ปุ่ม Export บน toolbar ของแท็บรายการสินค้า → ดาวน์โหลด .xlsx ทั้งหมด
2. **หมวดหมู่ / ยี่ห้อ** (สินค้า → มาสเตอร์ → แท็บ ยี่ห้อ / หมวดหมู่) ใช้ปุ่ม นำเข้า / ส่งออก (N) / Template + สลับ .xlsx|.csv ที่หัวตาราง ขั้นตอนเหมือนข้อ 1 หลังยืนยันตารางจะรีเฟรชเอง
3. **แบรนด์** (จัดการแบรนด์) และ **ผู้จำหน่าย** (จัดการผู้จำหน่าย) มีปุ่มชุดเดียวกันที่หัวหน้า สำหรับผู้จำหน่าย ลองแก้ชื่อโดยคงเลขผู้เสียภาษีไว้ → ต้องเป็น "อัปเดต" ไม่ใช่ "เพิ่มใหม่"
4. ตรวจ audit log ว่ามีรายการ action "นำเข้าข้อมูล" พร้อมจำนวน

## Mobile (iOS/Android)
`ImportExportScreen` ใช้โมดูลกลางทั้งการ parse, validate, apply และ export (ไม่มี parser แยกอีกแล้ว) แต่การเลือกไฟล์และการดาวน์โหลดยังทำได้เฉพาะบนเว็บ (`<input type=file>` / Blob) เพราะโปรเจกต์ยังไม่มี `expo-document-picker` / `expo-file-system` บน native ยังแสดงข้อความเดิม "รองรับเฉพาะเว็บในเวอร์ชันนี้" และปุ่มถูกปิด

## สิ่งที่ยังไม่ได้ตรวจ
- ยังไม่ได้คลิกทดสอบจริงในเบราว์เซอร์ (dialog เลือกไฟล์, การดาวน์โหลด, layout ของ modal) ที่ตรวจแล้วคือ bundle ของเว็บ build ผ่าน, type check ผ่าน และ logic ทั้งหมดผ่าน unit test
- ยังไม่ได้เปิดไฟล์ด้วย Microsoft Excel บน desktop จริง ที่ตรวจแล้วคือไฟล์ที่ SheetJS เขียนถูกอ่านกลับได้ครบ (ประเภทเซลล์ s/n ถูกต้อง) และ CSV มี BOM
- ยังไม่ได้ build native (Android/iOS) ด้วย `expo export` แต่ build `dist/xlsx.full.min.js` ไม่มี `require()` และถูกโหลดเฉพาะเมื่อใช้ .xlsx บนเว็บเท่านั้น
