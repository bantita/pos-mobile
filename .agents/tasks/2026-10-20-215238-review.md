# Xcellence POS parity: tax-invoice/cancellation/shift/license screens + web license/document settings + rebrand

This change brings the local D-drive project to parity with the live Xcellence POS deployment. It rebrands metadata and the PWA manifest to "Xcellence POS", adds four native sale/auth screens (TaxInvoice, DocumentCancellation, ShiftGate, LicenseActivation) wired into SaleNavigator and a native license gate in App.tsx, and adds two web screens (WebLicense, WebDocumentSettings) wired into WebNavigator under the existing `settings` permission. Stores gained license fields (`storeConfigStore`) and a `taxInvoiceEnabled` receipt flag. The approach follows sibling-screen conventions and the real design tokens rather than the steering doc's idealized API.

Watch for: the PWA `manifest.json` `description` (both `public/` and `dist/`) does not match the current live site's manifest description — confirmed. Everything else (screens, prop signatures, wiring, tokens, tsc≤13, tests) checks out.

**Verdict**: NEEDS_CHANGES

## High-level view

Rebrand metadata is almost exact against the live site: `app.json`, both manifests, and `dist/index.html` all carry "Xcellence POS", theme `#EA580C`, background `#FFF9F4`, `start_url /?target=pos`, matching icon/shortcut/screenshot counts, and the hashed `/_expo/static/js/web/index-508998427013033578ab597b23e3ca78.js` reference is byte-identical to `origin/main`. The one gap is the manifest `description` string, which diverges from the live manifest; notably the local `dist/index.html` meta description *does* match live, so the divergence is isolated to the manifest files.

The six screens exist with the exact required prop signatures and use only real exported tokens. Native screens follow the SafeAreaView + colored header + Ionicons + StyleSheet convention; web screens use `WebColors` + design-system `Space/Radius/Font`. Button components use the real `title` prop. Thai UI throughout, with loading/error/empty states present on the screens where they apply.

Wiring matches the spec: SaleNavigator registers `TaxInvoice` and `DocumentCancellation` (modal), Receipt params remain `{saleNo, payments}`, App.tsx routes native boot to `license` before `auth` and leaves the web branch untouched, and WebNavigator maps `licenses`/`documents`/`branches` to the `settings` permission key in both the `navigate()` guard and the render guard without touching the sidebar.

Verification reproduced locally: `npx tsc --noEmit` yields exactly 13 errors, all in pre-existing files (BranchSelector, DatePicker, PermissionMatrixScreen, RoleManageScreen, WebUserStaffScreen, errorTracking), none referencing task files. `npm run test` shows 39 passed with 3 suite-load failures from an environmental react-native/vite import-analysis issue in untouched test files — the documented baseline, no new failures.
